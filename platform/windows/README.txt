双击 ModbusAIStudio.exe 运行，不用安装。
可同时运行多个程序实例，也可用“文件 → 新建窗口”打开独立工作区。
右上角关闭按钮默认隐藏到托盘，采集继续；右键托盘图标选择“退出所有窗口”退出本实例。

顶部显示连接状态，可直接全部暂停 / 继续读取、切换只读模式。
通信报文可按错误、发送或接收筛选，配合字节查找；“清除筛选”恢复全部报文，计数区显示筛选、保留和累计条数。
“调试 → 检测寄存器”可自动定位、逐个寄存器、按点表分段、逐点独立验证或快速排查，找出读不通的点；可停止、复制结果、导出报告（Markdown 摘要、JSONL 请求与原始报文、CSV 失败清单）。
已有对应功能码的点表时默认按点表分段：连续点位按单次读取上限分段，异常段按每个点的完整宽度单独测试，结果列出点名、地址、类型与原因；整段读通的点记为“整段有返回（未逐点验证）”。
逐点独立验证先整段读、再每个点单独读，列出整段有返回、单独却读不通的点及整段返回的原始值，用来发现数据转发设备给空位补 0 的情况。
Modbus TCP 下收到功能码 89 原样回显请求地址和数量的帧时，记为非标准响应并立即结束这次请求，不当作异常码。
TCP 可直接按连接栏参数开始检测，不必先连接。检测使用独立连接，暂停常规轮询和常规重连；断线后自行重连并重试当前读取一次，反复断线的点列为读取出错，继续测试其他点。持续无法建连超过 30 秒保留结果后停止，检测结束时关闭检测连接，为原主会话重新建立常规连接并恢复原读取状态，避免晚到响应混入常规读取。串口和内置模拟器需先连接。
点表在后台导入，显示进度和预计还要多久，可取消；全部有效点位保留，自动补建读取窗口最多到 16 个，未自动建窗的点仍可按点表检测。
导入结果里的“修改站号…”、“读取 → 修改站号（Slave ID）…”或读取窗口右键，可一次改好全部读取窗口的站号；窗口用了几个站号时先选改哪一组。
晚到响应标出回的是哪条请求（发送时间、请求号、请求报文）和比超时晚了多久；事务号不是本连接发出的帧标为“非本连接的响应”，
多半是串口服务器 / DTU 把别的主站的响应转了过来，调大超时也收不到。

命令行工具 modbus-cli（单独的包：发布页里的 modbus-cli-x.y.z-windows-x64.zip，另有 macOS、Linux 的包）
  解压后在命令行运行 modbus-cli.exe，和本程序用同一套通信核心。加 -json 时每条命令输出一个 JSON 对象，
  方便脚本和 AI 调用；选项写在命令前面。退出码 0 成功，1 通信失败或回读不符，2 命令写错。
  modbus-cli [选项] read  <地址> <数量>   读寄存器（-type / -order / -scale 换算工程值）；-fc 1 读线圈、-fc 2 读离散输入
  modbus-cli [选项] write <地址> <值>     写入并立即回读核对；-fc 5 写线圈（0 / 1）
  modbus-cli [选项] detect               识别 Modbus TCP 还是 RTU over TCP
  modbus-cli [选项] scan [起始 结束]      扫描应答的站号，默认 1–247
  modbus-cli [选项] raw <PDU 十六进制>    发任意请求 PDU，例如 raw 08 00 00 12 34
  modbus-cli -points 点表.xlsx points    列出点表里的点（和“导入点表”认同样的文件）
  modbus-cli [选项] -points 点表 get [点名…]     按点名读工程值，带单位和枚举含义
  modbus-cli [选项] -points 点表 set 点名 值      按点表写一个点，检查可写和范围，回读判断是否生效
  modbus-cli [选项] probe [auto|single|quick] <地址> <数量>   检测寄存器，和“检测寄存器”同一套算法
  modbus-cli [选项] -points 点表 probe points|each           按点表分段 / 逐点独立验证；-report 报告.md 另存检测报告
  modbus-cli manual                      完整说明：全部选项、JSON 字段、退出码、示例
  常用选项：-target IP:端口、-port COM3 -baud 9600 -parity N、-mode rtu-over-tcp、-slave 站号、-timeout 3s、-trace
  例：modbus-cli -target 192.168.1.100:502 -json -type float32 -order CDAB read 40001 4

### 1.4.0 一键改站号，标注晚到响应，单独发布 modbus-cli；识别非标准 89 回显，新增逐点独立验证、快速排查和检测报告

- 导入点表后可一键修改站号：导入结果里的“修改站号…”、菜单“读取 → 修改站号（Slave ID）…”、读取窗口右键，一次改好全部读取窗口；窗口用了几个站号（同一总线上几台设备）时先选改哪一组。改站号保留窗口里设的数据类型；扫描从站后的“读取窗口改用 Slave N”同样保留。
- 晚到响应标出回的是哪条请求：发送时间、请求号和请求报文，以及比超时晚了多久，这期间又发了几条请求；在两次请求之间到达的只能给出范围。响应顺序和请求顺序不同（例如第一条 30 秒才回、第二条 10 秒就回）时，Modbus TCP 按事务号各自对上。读取窗口的“超时改为 N ms”按那条请求的实际用时给值。
- Modbus TCP 收到事务号不是本连接发出的帧，标为“非本连接的响应”，状态栏单独计数：多半是串口服务器 / DTU 把别的主站的响应也转给了这个连接，调大超时也收不到；超时分析会说明，并建议停掉其他主站或关掉多主机共享、多中心转发。连在一起收到的几帧拆开逐帧说明。
- 命令行工具 modbus-cli 单独发布，Windows x64、macOS Intel / Apple Silicon、Linux x64 / ARM64 各一个包：新增读写线圈和离散输入、扫描站号（scan）、发任意 PDU（raw）；加 -json 时每条命令输出一个 JSON 对象，退出码区分成功、通信失败和参数错误，方便脚本和 AI 调用；modbus-cli manual 打印完整说明，包里的 README.txt 就是它。
- 发布前每个包都在对应的系统和 CPU 上运行测试：Windows x64、macOS Intel / Apple Silicon、Linux x64 / ARM64。
- Modbus TCP 下，读请求收到事务号、Unit ID 都对上、功能码 89 原样回显地址和数量的帧时，记为“非标准响应”并立即结束请求，不再等到超时；报文解析和自动分析不再把 89 后面的地址字节显示成“非法数据值 03”。标准异常必须正好 2 字节，带多余字节的按不匹配处理。超时前收到过对不上的帧时，说明设备其实回过话。
- 检测结果分开“单独读取可读”和“批量有返回（未单独验证）”：批量读通不再算作每个地址都能读，按点表分段里整段读通的点标为“整段有返回（未逐点验证）”，所以“可读”的数字会比以前小。
- 新增“逐点独立验证”：先整段读、再每个点按宽度单独读，列出整段有返回、单独却读不通的点和整段返回的原始值，提示可能是设备给空位补 0。
- 新增“快速排查”：批量读范围，从全 0 段里抽查最多 4 个点单独读，读不通时读控制点并做边界对照（起点不变、只多一个已读通的点，各读两次），验证请求最多 16 次；只说抽样到的事实，可一键接着做完整检测。
- 检测结果可“导出报告”：Markdown 摘要（检测条件、各读取方式的请求统计、结果、完整性）、JSONL（每条请求和等待期间收到的全部原始帧）、CSV 失败清单；写完读回核对，失败时不留下半截文件。
- 异常收发（超时、异常、非标准响应、不匹配、晚到、校验错误、连接错误）另存进数据库的 anomalies 表，每条带同一请求的发送帧；历史记录新增“异常报文”页，不受 5000 条限制。
- 打开 / 保存工作区、历史记录读连接列表、保存报文、导出 AI 报告改在后台进行，大文件或慢磁盘不再卡住界面；读得慢时可取消，保存先写临时文件再替换，出错时原文件不受影响。
- 读取窗口收到非标准响应时，一键处理是“检测这个范围”，不建议减数量、换功能码或扫站号；扫描从站把 89 回显也算作该站号有设备作答。

### 1.0.2 独立点位检测，连续寄存器分段测试

- TCP 点位检测使用独立连接，可以在常规连接反复重连时测试，也可以直接按连接栏参数开始检测。检测期间暂停常规轮询和重连；结束时关闭检测连接，为原主会话重新建立常规连接并恢复原读取状态，避免晚到响应混入常规读取。
- 有对应功能码的点表时默认按点表分段；连续点位按 Modbus 单次读取数量上限合并读取，异常段按每个点的完整宽度单独测试，优先列出读不通的点、地址、名称、类型和原因。
- 检测连接断开后自行重连，重试当前读取一次；某个点反复断开时记为读取出错，继续测试其余点。持续无法建连超过 30 秒停止并保留结果，未完成复核的点仍为未检测。

### 1.0.1 重连检测与 1000 点点表导入优化

- TCP 检测断线后保留进度，等待常规连接自动重连后继续；反复断线的范围逐点复核，尚未复核的点保持未检测。
- CSV / XLSX 在后台导入，可取消并保留原点表；完整点表保留，自动补建读取窗口最多到 16 个，避免大量分散点位建窗拖慢界面，覆盖 1000 点导入测试。
- XLSX 按行解析，忽略空白格式单元格，并限制解压大小和单元格数量，避免大型或异常文件占用过多内存。

### 1.0.0 读取区优先显示寄存器，分析断开原因，按点表检测寄存器

- 读取区优先显示寄存器：
  - 导入点表、打开示例或工作区一次建多个读取窗口时，最大化显示第一个，读取区上方的标签列出全部窗口（编号和地址范围），点一下切换，读取失败的窗口标签标红；要同时看几个窗口，用“窗口 → 平铺”或“层叠”。
  - 修正 0.11.15 的层叠位置：不到 8 个窗口时从左上角开始错开，不再整体挤到右下角、每个窗口只剩一两行。
  - 读取窗口先保证表格显示全部行，提示和 Tx 统计行只用剩下的空间，放不下时在控制条下方滚动查看；读取出错时，只要表格还能留出表头和 3 行，错误说明和一键处理照常显示。
  - “视图 → 通信报文与解析面板”（Ctrl+J）可隐藏下方面板，读取区占满主窗口，多显示约 6 行寄存器；收发照常记录，下次启动沿用该设置。“视图 → 恢复默认窗口大小与布局”会重新显示面板。
- 检测寄存器增加“检测方式”：“逐个寄存器”每个地址单独读一次，异常码不打断；“按点表分段”把地址相连的点合成一段读一次，读不通的段逐点再读，按点列出读不通的点（地址、名称、类型、原因）。
- 分析断开原因：从读写错误判断连接是怎么断的——设备关闭（收到 FIN）、被复位（收到 RST）、本机重传没有回应后中止、网络不可达，结合断开时机给出原因；通信报文里连接错误那一行写明断开方式。
- 连接报文：日志记一条“连接建立”，写明本机端口和设备地址；重连成功也写明新连接的两端地址。读取失败和连接断开的日志附带出错前这条连接上最近 12 条收发。
- 安装包变小：Windows 压缩包从 15.8 MB 降到约 10 MB，macOS 安装包改用 LZMA 压缩，也明显变小。不再自带 Fyne 的彩色 emoji 字体，emoji 改用系统字体显示。
- Windows 包不再附带命令行工具 modbus-cli.exe 和 modbus-sim.exe，需要时从源码编译；程序里的内置模拟器不受影响。自动更新不会删除旧版本留下的这两个文件。
- 内置模拟器默认不勾选，打开程序直接填设备地址就能连接；“读取 → 打开换热站示例”仍会自动勾选内置模拟器并连接。
- 记住连接参数：协议、目标地址、波特率、数据格式、串口和超时在连接时和关闭主窗口时保存，下次启动沿用；内置模拟器不沿用。

### 0.11.15 导入点表显示全部窗口

- 点表地址分散、导入时按地址段建了多个读取窗口时自动层叠：地址最小的窗口在最上面，其余露出标题栏（标题里有地址范围），点标题栏切换，或用“窗口 → 平铺”同时查看。此前其余窗口被第一个窗口整个盖住，看起来只导入了最前面一段连续寄存器。打开工作区同样层叠；超过 8 个窗口时最上面 8 个的标题栏都露出来。
- 导入设备属性表时，与前面的点地址重叠的行（常见于 REAL 点地址只隔 1）先汇总说明重叠的行数和原因，再逐行指出被哪个点占用，例如“地址 40005 被‘3’占用：它是 FLOAT32，占 40004–40005”。

### 0.11.14 扩大寄存器读取区域

- 主窗口上方的读取窗口区按默认比例实际占到约七成高度：1040 × 680 默认窗口下高度增加约 60 像素，读取窗口可多显示约两行寄存器；“视图 → 恢复默认窗口大小与布局”使用相同比例。
- 通信报文的操作、筛选和计数合并为一行，随面板宽度换行；空列表提示改为单行。报文区仍完整显示按钮、筛选和至少一行报文，可拖动分隔线调整。

### 0.11.13 AI 交互与字节序修复

- 报告的 E 编号可点击查看发送时的冻结证据；发送内容提供证据列表、详情复制和完整 JSON，模型外部链接和图片继续按文本显示。
- “更新当前证据”保留绑定对象并收集对应新响应；“使用当前选择”切换到解析区当前对象。多行问题支持 Ctrl / ⌘ + Enter；快速提问提供检查步骤和补充证据问题，分析进度可取消。
- 新报文通过 connection_id + request_id 关联收发；历史来源仅使用同一文件 / 会话。旧记录和无法确认归属的晚到帧标为未知，晚到标题也不声称请求地址。
- 检测结果的“AI分析结果”冻结可读、非法地址、未响应、无法判断、未检测和停止原因，不借用当前读取状态。
- 解析区和菜单“调整字节序…”支持普通窗口及局部格式；暂停或离线时立即重解码，保留原始读数。窄窗口设置按钮换行，内容可滚动到底部。
