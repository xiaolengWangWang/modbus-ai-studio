Modbus AI Studio {{VERSION}}（Windows x64 绿色版）

双击 ModbusAIStudio.exe 运行，不用安装。
可同时运行多个程序实例，也可用“文件 → 新建窗口”打开独立工作区。
右上角关闭按钮默认隐藏到托盘，采集继续；右键托盘图标选择“退出所有窗口”退出本实例。
“视图 → 关闭按钮隐藏到托盘”可修改关闭行为；窗口大小自动适配屏幕并记住上次设置。
顶部显示连接状态，可直接全部暂停 / 继续读取、切换只读模式。
通信报文可按错误、发送或接收筛选，配合字节查找；“清除筛选”恢复全部报文，计数区显示筛选、保留和累计条数。
“调试 → 检测寄存器”可自动定位、逐个寄存器或按点表分段检测，找出读不通的寄存器，区分可读、非法地址（异常 02）、无法判断和未检测；可停止、复制结果。
“调试 → AI 诊断助手”或解析面板“AI解释”打开 DeepSeek：在“模型设置”填写 API Key、保存并测试连接，再预览发送内容后开始分析。
读取故障行“AI分析”直接绑定该读取窗口；日志和历史日志也能分析。助手顶部显示对象与所选地址，报告分节显示，可复制或导出带冻结证据的 Markdown 文件。
Windows 使用当前用户 DPAPI 加密保存密钥。默认不发送寄存器值和原始报文，勾选后才包含；AI 提供人工检查建议，不执行设备操作。
请看中文是否为微软雅黑 UI、150% 缩放下窗口是否完整、
标题栏和任务栏的小图标是否清晰。首次启动如果仍慢，请发送
%AppData%\ModbusAIStudio\app.log（里面记录了各启动阶段耗时）。
- 系统要求：Windows 10 / 11 64 位。不支持 Windows 7 / 8。
- 需要显卡支持 OpenGL 2.1，不支持时程序会弹窗说明。处理办法：下载 Mesa3D 软件渲染版的
  opengl32.dll（https://github.com/pal1000/mesa-dist-win 的 x64 目录），放到 exe 同一目录再运行。
- 报文记录从 %AppData%\ModbusAIStudio\packets.db 开始，单个数据库文件上限 50 MB。
  写满后自动创建 packets-000001.db 等编号文件，旧文件保留，不自动删除。
  “历史记录”可选择文件查看；所有 .db 文件也可用 SQLite 管理工具打开。

### 1.0.0 读取区优先显示寄存器，分析断开原因，按点表检测寄存器

- 读取区优先显示寄存器：
  - 导入点表、打开示例或工作区一次建多个读取窗口时，最大化显示第一个，读取区上方的标签列出全部窗口（编号和地址范围），点一下切换，读取失败的窗口标签标红；要同时看几个窗口，用“窗口 → 平铺”或“层叠”。
  - 修正 0.11.15 的层叠位置：不到 8 个窗口时从左上角开始错开，不再整体挤到右下角、每个窗口只剩一两行。
  - 读取窗口先保证表格显示全部行，提示和 Tx 统计行只用剩下的空间，放不下时在控制条下方滚动查看；读取出错时，只要表格还能留出表头和 3 行，错误说明和一键处理照常显示。
  - “视图 → 通信报文与解析面板”（Ctrl+J）可隐藏下方面板，读取区占满主窗口，多显示约 6 行寄存器；收发照常记录，下次启动沿用该设置。“视图 → 恢复默认窗口大小与布局”会重新显示面板。
- 检测寄存器增加“检测方式”：“逐个寄存器”每个地址单独读一次，异常码不打断；“按点表分段”把地址相连的点合成一段读一次，读不通的段逐点再读，按点列出读不通的点（地址、名称、类型、原因）。
- 分析断开原因：从读写错误判断连接是怎么断的——设备关闭（收到 FIN）、被复位（收到 RST）、本机重传没有回应后中止、网络不可达，结合断开时机给出原因；通信报文里连接错误那一行写明断开方式。
- 连接报文：日志记一条“连接建立”，写明本机端口和设备地址；重连成功也写明新连接的两端地址。读取失败和连接断开的日志附带出错前这条连接上最近 12 条收发。
- 安装包变小：Windows 压缩包从 15.8 MB 降到约 10 MB，macOS 安装包改用 LZMA 压缩，也明显变小。不再自带 Fyne 的彩色 emoji 字体，emoji 改用系统字体显示。
- Windows 包不再附带命令行工具 modbus-cli.exe 和 modbus-sim.exe，需要时从源码编译；程序里的内置模拟器不受影响。自动更新不会删除旧版本留下的这两个文件。
- 内置模拟器默认不勾选，打开程序直接填设备地址就能连接；“读取 → 打开换热站示例”仍会自动勾选内置模拟器并连接。
- 记住连接参数：协议、目标地址、波特率、数据格式、串口和超时在连接时和关闭主窗口时保存，下次启动沿用；内置模拟器不沿用。

### 0.11.15 导入点表显示全部窗口

- 点表地址分散、导入时按地址段建了多个读取窗口时自动层叠：地址最小的窗口在最上面，其余露出标题栏（标题里有地址范围），点标题栏切换，或用“窗口 → 平铺”同时查看。此前其余窗口被第一个窗口整个盖住，看起来只导入了最前面一段连续寄存器。打开工作区同样层叠；超过 8 个窗口时最上面 8 个的标题栏都露出来。
- 导入设备属性表时，与前面的点地址重叠的行（常见于 REAL 点地址只隔 1）先汇总说明重叠的行数和原因，再逐行指出被哪个点占用，例如“地址 40005 被‘3’占用：它是 FLOAT32，占 40004–40005”。

### 0.11.14 扩大寄存器读取区域

- 主窗口上方的读取窗口区按默认比例实际占到约七成高度：1040 × 680 默认窗口下高度增加约 60 像素，读取窗口可多显示约两行寄存器；“视图 → 恢复默认窗口大小与布局”使用相同比例。
- 通信报文的操作、筛选和计数合并为一行，随面板宽度换行；空列表提示改为单行。报文区仍完整显示按钮、筛选和至少一行报文，可拖动分隔线调整。

### 0.11.13 AI 交互与字节序修复

- 报告的 E 编号可点击查看发送时的冻结证据；发送内容提供证据列表、详情复制和完整 JSON，模型外部链接和图片继续按文本显示。
- “更新当前证据”保留绑定对象并收集对应新响应；“使用当前选择”切换到解析区当前对象。多行问题支持 Ctrl / ⌘ + Enter；快速提问提供检查步骤和补充证据问题，分析进度可取消。
- 新报文通过 connection_id + request_id 关联收发；历史来源仅使用同一文件 / 会话。旧记录和无法确认归属的晚到帧标为未知，晚到标题也不声称请求地址。
- 检测结果的“AI分析结果”冻结可读、非法地址、未响应、无法判断、未检测和停止原因，不借用当前读取状态。
- 解析区和菜单“调整字节序…”支持普通窗口及局部格式；暂停或离线时立即重解码，保留原始读数。窄窗口设置按钮换行，内容可滚动到底部。
