## 连不上

| 提示 | 原因和处理 |
| --- | --- |
| 连接被拒绝 | IP 对，但这个端口没有 Modbus 服务：检查端口（默认 502），确认设备的 Modbus TCP 功能已开启 |
| 连接超时 | 设备不在线或网络不通：先 ping 设备 IP，检查网线、网段、防火墙 |
| 串口打不开 | 串口被别的程序占用（包括另一个主窗口）；USB 转 485 刚插上时等几秒，串口列表会自动刷新 |

## 连上了但一直超时

- **Modbus TCP 一直超时**：设备可能是 RTU over TCP（串口服务器、透传模块常见），点“识别”自动判断。经过网关访问 485 设备时，Slave ID 要填网关后面那台设备的站号。
- **RTU over TCP 一直超时**：设备可能其实是 Modbus TCP；串口服务器的波特率、校验位要和设备一致。
- **串口一直超时**：依次检查波特率 / 校验位 / 停止位、Slave ID、A / B 线是否接反、终端电阻、总线上是否还有别的主站。不确定参数时用“连接 → 扫描串口参数”，不确定站号时用“调试 → 扫描从站地址”。
- **同一连接上别的窗口正常，只有这个窗口超时**：链路没问题，多半是这个 Slave ID 不存在，或这段地址设备应答特别慢。

## 连接断开

TCP 类连接断开后会自动重连（间隔 1 / 2 / 5 / 10 s），重连期间暂停轮询，重连后自动恢复。断开的原因按发生的时机分析，显示在读取窗口里：

| 时机 | 可能的原因 | 一键处理 |
| --- | --- | --- |
| 连上就断，还没发请求 | 设备的连接数满了（组态软件、别的上位机占着）、IP 白名单，或这个端口不是 Modbus 服务 | |
| 每次发出某条请求后立刻断，一次正常响应都没有 | 协议格式不对：Modbus TCP 设备收到 RTU / ASCII 帧会直接断开 | 识别协议 |
| 每次发出某条请求后立刻断，其他请求正常 | 设备不接受这个站号、功能码或地址（会指出是哪条请求） | 暂停这条请求，其他窗口照常 |
| 空闲一段时间后断 | 设备有空闲超时 | 缩短扫描周期 |
| 用了一阵后随机断 | 网络不稳或设备重启（会给出断开次数和平均间隔） | |

网线被拔掉时 TCP 不会马上报错，表现为超时。串口断开多半是 USB 转 485 被拔掉或驱动掉线，不会自动重连，插回后点“重新连接”。

每次断开和重连都记在报文库的 `events` 表里，“调试 → 历史报文”的会话列表显示每次连接断开了几次。

## Err 不为 0

`Err` 是这个读取窗口出错的次数。出错的那条请求在通信报文里用颜色标出，可以用“仅错误”筛选：

| 报文里的标记 | 含义 |
| --- | --- |
| 超时（无数据） | 超时时间内没有收到响应 |
| 晚到响应，已丢弃 | 设备应答了，但超过了超时时间。把超时调大即可，自动分析会算出合适的值 |
| CRC / LRC 错误 | 响应在传输中损坏：波特率、校验位不一致，或线路干扰、接地屏蔽不好。读请求会自动重试 1 次，偶发可以忽略 |
| 异常 | 设备收到了请求但拒绝执行，见下面的异常码 |

## 异常码

| 异常码 | 名称 | 含义和处理 |
| --- | --- | --- |
| 01 | Illegal Function | 设备不支持这个功能码。读保持寄存器（03）报这个就试 04，反之亦然 |
| 02 | Illegal Data Address | 地址越界。最常见的是地址差 1（手册按 1 起始，协议按 0 起始），或者读取范围跨过了设备没定义的地址；自动分析可以逐个探测哪些地址能读 |
| 03 | Illegal Data Value | 数量超过设备单次读取上限（不少设备只允许 32 或 64 个），或写入值超出设备允许的范围 |
| 04 | Slave Device Failure | 设备内部错误，检查设备状态 |
| 05 | Acknowledge | 设备已接受，需要较长时间处理。写入验证会照常回读 |
| 06 | Slave Device Busy | 设备忙，降低轮询频率 |
| 08 | Memory Parity Error | 读文件记录（FC20 / FC21）时设备存储校验出错 |
| 0A | Gateway Path Unavailable | 网关里没有配置到这个 Slave ID 的路由 |
| 0B | Gateway Target Device Failed to Respond | 网关收到了请求，但它后面的 485 设备没应答：检查 Slave ID、网关串口侧的波特率 / 校验位、485 接线 |

## 读到的值不对

- **整体偏了一个地址**：手册地址 40001 对应协议地址 0。用 40001 写法输入地址就不会错；如果设备手册本身按 0 起始编号，起始地址减 1。
- **浮点数是很大或很小的怪数（灰色显示）**：字节序不对。单击值看右下角的解析，四种字节序里标“合理”的那个就是；自动分析也会直接建议。见 [字节序](points.md#字节序)。
- **差 10 倍、100 倍**：点表里的倍率不对。
- **32 位、64 位值的后几个寄存器显示“—”**：正常，一个值显示在它的第一个寄存器上。
- **64 位大数最后几位不对**：程序本身按整数精确处理，不会丢位。如果写入后回读低位变了，多半是设备内部用 double 保存 64 位整数，超过 2^53 的值存不下全部位数，写入验证会判为“值不符”并说明。

## 写入失败

写入后会回读验证，结论的含义见 [使用说明 · 写入与控制验证](guide.md#写入与控制验证)。

- **写入按钮是灰的**：没连接、没选中值、开着只读模式、选中的是输入寄存器或离散输入，或者点表里这个点标为只读（字符串点也是只读）。
- **未生效**：设备回了写成功，但值没变。检查地址、点位是否只读、设备是否在本地 / 手动模式、是否有联锁条件。
- **被覆盖**：PLC 程序在周期性地写这个地址，要在程序里改，或找能写的那个地址（例如设定值而不是实际值）。
- **值不符**：多半是写入字节序和采集字节序不一致，或倍率配错；能对上时会直接指出用哪种字节序。

## 报文记录在哪里

| 系统 | 数据库位置 |
| --- | --- |
| Windows | `%AppData%\ModbusAIStudio\packets.db` |
| macOS | `~/Library/Application Support/ModbusAIStudio/packets.db` |
| Linux | `~/.config/ModbusAIStudio/packets.db` |

保留 7 天。表结构和查询出错请求、断开记录的 SQL 见 [使用说明 · 报文记录与历史](guide.md#报文记录与历史)。

## 安装与运行

- **Windows 双击没反应或弹窗说显卡不支持 OpenGL**：远程桌面、虚拟机、老工控机常见。下载 [Mesa3D](https://github.com/pal1000/mesa-dist-win) 软件渲染版，把 x64 目录里的 `opengl32.dll` 放到 `ModbusAIStudio.exe` 同一目录再打开。运行日志在 `%AppData%\ModbusAIStudio\app.log`。
- **Windows 7 / 8**：不支持，需要 Windows 10 / 11 64 位。
- **macOS 提示无法打开**：安装包是 ad-hoc 签名，第一次打开要在“系统设置 → 隐私与安全性”里点“仍要打开”。
- **macOS 想同时开两个进程**：一般用“文件 → 新建窗口”就够了；确实需要第二个进程时运行 `open -n "/Applications/Modbus AI Studio.app"`。
- **Linux**：暂时没有安装包，可以从源码编译，见 [开发与发布](development.md)。
